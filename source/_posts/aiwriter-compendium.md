## ✍️ 01 写匠概述

**产品定位**：为写作爱好者与专业作家设计的专业写作系统。核心理念是把「写三千字」拆成「写十张三百字的卡片」，每一张都短到能一口气写完，动笔于是不再是难事。写一部书、一篇论文或任意长文，都可以从一张卡片开始。

**隐私与本地**：本地写作永久免费；首次使用需联网登录一次，之后可离线写作，数据留在本机，断网照写。项目就是一个文件夹，卡片就是明文文件，不锁进私有数据库。

### 三种格式，各取所需

- **.txt 纯文本**：适合写诗。没有标记语法挡在你和文字之间，分行就是分行，留白就是留白。
- **.md Markdown**：适合日常文章。最通用的写作格式，写完直接发到任何地方，不必再转一道。
- **.typ Typst**：适合科技论文。新兴科技出版格式，可取代 LaTeX；公式、图表、交叉引用一键预览编译。

### 下载与平台

**macOS**（Apple Silicon 与 Intel 各一个安装包，macOS 14+）已支持；**Windows** 开发中；**Linux** 规划中。本地写作永久免费，首次联网登录一次账号后即可离线使用。

## 🔧 02 核心功能

### 更高效的写作流程

任何一个稍大的写作项目，永远是从混乱走向清晰。写匠拆成两步：快写出第一版，再慢改成下一版。

- **新建项目**：打开就写，不用伺候设置；挑模板、起个名，写下第一行。
- **快写第一版**：三千字拆成十张三百字卡片，每张都能一口气写完，一键组合成文。
- **慢改成新版**（会员能力）：校对润色逐条指到原句，可整批采纳、刚采纳完撤回。
- **定稿导出**：导出 PDF / EPUB / DOCX / Markdown，Typst 排版引擎已内置。

### 三种写作模式

| 模式 | 快捷键 | 作用 |
|---|---|---|
| 卡片列表 | ⌘1 | 一屏铺开这一章的所有卡，随手挑一张接着写 |
| 卡片编辑 | ⌘2 | 一次只面对一张卡，写完这三百字，今天就算数 |
| 卡片拼接 | ⌘3 | 卡片接成一部真书，翻页预览 |

### 更强大的 AI 功能

写作台右栏就是一个 AI 助手，分四格：校对、润色、分析、排版。它只提建议，采不采纳由你。会员能力。

- **校对**：错别字、用错的字词、标点、语病，逐条给出建议，精确定位到原句。
- **润色**：管的不是对错，是好坏——哪里可以更准、更短、更有力。
- **分析**：节奏、意象与情绪、风格画像，把你的写作规律摊开给你看。
- **排版**：把正文交给 AI，生成 Typst 排版源码，一键存成排版卡。

### 实时写作统计（⌘/ · 本机不计费）

写着按 ⌘/，这一张卡的画像就摊在旁边，五个维度的数由程序当场算，不联网、不计费，免费档照用。维度包括：

- **整体**：可读指数、字词句段数量
- **字词**：五音、词长、词性、常用与生僻词
- **句法**：长短句节拍、单复句、陈述疑问感叹
- **篇章**：段长、反复出现的词
- **元话语**：语篇类宜删、人际类宜增

### 数字人文分析（会员能力）

- **节奏**：分句、句长与节拍，由程序算
- **意象与情绪**：情绪、季语、生存母题，每个词必须真的出现在原文里
- **风格画像**：语言质地概括

自研校对与排版大模型已发预览版，可下载到本机运行（经活水模型 42model），学术与个人使用免费。

### 更精美的排版设计

针对图书与学术论文的出版做了大量设计，并自研了一个 **Typst 排版大模型**，足以支持极为复杂的版式。公式、图表、交叉引用、脚注尾注，一应俱全。

### 隐私与安全：三件事

- **明文格式**：项目就是一个文件夹，卡片就是 .txt / .md / .typ 文件，随时能用别的工具打开。
- **本地优先**：登录一次后，写作、整理、重排、导出都在本机，离线照常，不会静默上传。
- **自动保存**：边写边自动保存；版本历史默认开，⌘S 留版本，误删从回收站捡回。

## 🖥️ 05 命令行

写匠背后有一个命令行程序 `aiwriter`：建卡、查找、导出这些活是它在做，桌面版把它们画成了界面。想批量处理、写脚本或让 AI 编程助手动手时再用它。

### 命令行入门

**装进终端**：打开写匠，进 **设置 › 外观 › 界面 ›「命令行工具」**，点「安装到终端」，macOS 会请你输一次密码。装好之后敲：

```bash
$ aiwriter --help
```

**找到你的项目**：项目就是一个 `<书名>.aiw` 文件夹，默认在 `~/aiwriter`。在项目文件夹里敲命令，或用 `--project` 指一下。

**四组常用命令**：

| 分组 | 命令 | 作用 |
|---|---|---|
| 项目 | `aiwriter new 我的小说` | 新建一本（落在 ~/aiwriter 下） |
| 项目 | `aiwriter projects ls` | 列出所有项目，带字数、卡数 |
| 写作 | `aiwriter ls` | 按大纲顺序列出所有卡 |
| 写作 | `aiwriter show <编号>` | 看一张卡的正文 |
| 写作 | `aiwriter add --title 第一章 --body 雨下了一整夜。` | 新建一张卡 |
| 写作 | `aiwriter find 雨` | 在这本书里找 |
| 写作 | `aiwriter rm <编号>` | 删一张卡——进回收站，可还原 |
| 成品 | `aiwriter pdf` | 导出 PDF |
| 成品 | `aiwriter docx --out 我的小说.docx` | 导出 Word，--out 说放在哪儿 |
| AI 与云 | `aiwriter ask 雨夜` | 把写过的相关卡片摆出来（不联网） |
| AI 与云 | `aiwriter analyze` | 写作统计：整体 / 字词 / 句法 / 篇章 |

注意：`aiwriter ls` 每张卡前那 8 位只是编号开头，`show / rm` 要完整编号——用 `aiwriter ls --json` 查。每条命令都能加 `--help`。

| `aiwriter auth` | 云端账号：登录 / 退出 / 看状态 |
| `aiwriter backup` | 云备份：加密备份到云上，换电脑取得回 |
| `aiwriter serve` | 后台：替你做备份、整理检索索引 |

#### 带子命令的命令（9 组）

下面这些命令后面还要再接一个词，如 `aiwriter backup status`。

| 命令 | 子命令 |
|---|---|
| `aiwriter version` | status · enable · disable · save · log · show · counts · migrate · restore · record-check |
| `aiwriter chat` | ls · show · rm · new · add · answer |
| `aiwriter tag` | set · rm · list |
| `aiwriter work` | show · in · out · follow |
| `aiwriter corpus` | find · register · ls |
| `aiwriter projects` | set-title · ls · stats · dir · move-to · new · prune · trash · rm |

| `aiwriter engine / model / serve / backup / auth / prefs / record / ai / font / log` | 各有细分（use/status/install… 等） |

每条命令都认 `--project <PROJECT>`（指定项目）与 `--json`（输出 JSON，桌面与网页版靠它拿结果）。

### 让 AI 编程助手调用写匠

Claude Code、Codex 会在终端敲命令。把写匠的命令行交给它们，就能替你做批量的活：拆卡片、排大纲、导出成稿、统计全书。

它们要知道的几件事：

- **一律加 --json**——输出是 JSON，程序读得懂；判成没成只看退出码。
- **先列、再按编号动**——用 `aiwriter ls --json` 拿到完整 id，再 show / edit / rm。
- **改正文走标准输入**——`aiwriter edit <id> --stdin < 文件`，历史默认开。
- **删除可逆，彻底删不是**——`rm` 进回收站；`trash purge / trash rm` 不可恢复。
- **目录卡链接用相对路径**，层级由你写出来（每两空格缩一级），不按文件夹猜。

**给它的一段说明（CLAUDE.md / AGENTS.md）**：

```text
这是一本用写匠写的书。读写卡片一律用命令行 aiwriter，不要直接改 .aiw 文件夹里的文件：
- 所有命令加 --json；先用 aiwriter ls --json 拿到卡片编号，再按编号操作。
- 判成没成只看退出码：0 是成了；命令本身写错时退出码是 2、stdout 是空的。
- 看正文：aiwriter show <编号> --json
- 改正文：把新正文写进一个文件，再 aiwriter edit <编号> --stdin < 那个文件。
- 新建：aiwriter add --title <标题> --body <正文> --json；放进文件夹加 --parent <文件夹编号>。
- 编号一律用 ls --json 里完整的 id；也可以直接写相对书根的路径，比如 _cards/卷1/卷1.md。
- 删除用 aiwriter rm <编号>（进回收站，可恢复）。不要运行 trash purge / trash rm，除非我明确同意。
- 不确定某条命令怎么用，先跑 aiwriter <命令> --help。
```

> **!** 为什么不让它直接改文件：写匠在 .aiwriter 里记着大纲顺序、状态和历史。走命令行，每一步都会留历史、进回收站，出了错你回得去。

#### 第五章 · 让书成形：插图、脚注、公式与导出

- **插图**：把图片粘贴或拖拽进卡片即插入一张图，方括号里的文字是图注。
- **脚注**：句末写「r1」，另起一行写「r1」和正文，就是一条脚注。脚注集中排在书末注释页。
- **公式**：写在美元符号之间。估篇幅：设全文 N 字、每页约 a 字、前置页 b 页，页数约 *P = N/a + b*。
- **导出 PDF**：在大纲里选中全书目录，按 Ctrl+导出选 PDF，得到一本排版好的书，可打印或交出版社。

> **! 操作提示**：在「全书目录」处进入「卡片拼接」与「导出」PDF；不要在「根目录节点」操作。刚上线时「目录卡」与「自然拼接」两种模式打架，当晚版本已统一修复。

### 用户初体验 · 李峻：写匠初体验

> 开智学堂 · AI 时代的元学教育 ｜ 全文收录

**小编的话**：为知笔记创始人李峻老师研发了多年笔记软件。写匠发布后，他把自己 2 GB 的笔记导了进去，试用写匠。一位研发笔记软件多年的人，用写匠是什么体验？来看～

写作很苦。有些苦值得吃，比如想清楚一件事，找到证据，删掉舍不得的段落，一遍遍重写。有些苦不值得，比如整理文件夹，翻找旧稿，恢复误删的版本，调格式。写匠想做的，是替作者免掉后一种苦。

**一条旧日记**

2014 年，我因为跑步开始研究心理学，由此认识了阳志平老师（老阳），也认识了开智。后来，老阳向我力推认知科学。

我的 AI Vault 里存着一条 2020 年 3 月 19 日的日记：「异常兴奋，和老阳讨论 How to Take Smart Notes。」那天我们聊卢曼卡片，聊 Roam Research。老阳说，这类工具都有缺陷。此后六年多，我们亦师亦友，一直在聊怎样用工具帮人思考和创作。这个月，他交出了自己的答案，就是写匠。

写匠是给认真写作的人用的，比如准备写书、写专著和论文的人，还有攒了多年博客、笔记和卡片，却始终没能把它们写成作品的人。偶尔写篇短文，Word 就够了；想让 AI 代写，写匠也不合适。它从头到尾都以作者为中心。

**卡片写作**

老阳说，写作有三组矛盾。一是快写和慢改。灵感记得很快，三千条笔记却未必能写成一本书。二是混沌和清晰。真实的写作满是素材、草稿和废稿，软件却只给你一份干净的文档。三是单文档和多文档。一句话、一篇文章、一个知识库是三种尺度，今天的一条灵感明天会发展成什么，谁也说不准。归结起来，作品的尺度一直在变，工具却要你提前决定。

写匠把从灵感到成书的每一步都放进同一个项目。灵感先记成卡片，再从旧材料里找出相关的卡片，一起组成章节，慢慢修改；改坏了可以退回，最后排版成书。

一篇三千字的文章，可以按标题拆成十张三百字的卡片，一次只写一张，写完再合并回去；合并得不满意，还能撤回。写三百字和写三千字，心理压力很不一样。

成稿排出来像一本真书时，哪里单薄、哪里该补，一眼就能看出来。

不过，工具只提供操作。拆分只需按一个按钮，可是察觉自己被三千字吓住，决定按论点而不是按字数拆，写完回头检查每张卡片是否仍在为全文服务，都得靠作者自己。什么时候改一句话，什么时候重排一章，什么时候停下来通读整本书，这种判断就是元认知。写匠能让每一次判断更快、代价更小，却不能替你判断。

卡住的时候，不妨先问自己：卡住的是材料、结构、表达，还是标准？

所以写匠用起来并不轻松，它是一套需要慢慢内化的方法。开智一向实事求是，写匠也一样。它能替你省下许多杂事，思想、取舍和重写的苦，仍然由你承担。

**明文与本地**

写匠替你承担的是另一部分。版本自动保存，组合可以撤回，随时可以回退，所以你敢删、敢改，也敢推倒重来。排版交给 Typst 和 AI，你不必去记排版语法。把力气花在整理目录上并不值得，整理文档带来的那点满足感，也不值得沉迷。

我把自己 2 GB 的 Markdown 笔记库导进了写匠。材料这么多，它依然稳定，依然快。

写匠的项目是明文的，任何编辑器都能打开；索引建在本地；云备份先在本地加密，云端只存密文。

多年积累的卡片、草稿和版本，首先属于作者。只有外部记忆足够可靠，人才敢把记忆托付给它。

**安静的 AI**

写匠里的 AI 很安静。它帮你检索、联想、分析、校对和排版。对话里的总结附带引用，点一下就能回到原来的卡片；只需要一句，就只复制那一句。

老阳给校对模型定了一个标准：找得全，还要忍得住。作家的有些「毛病」其实是风格。AI 挑的问题越多，你就越要一条条去否决。每条建议都有成本，少一条错误的建议，就少一份负担。为这种不抢作者位置的克制，我愿意付费。

**作者与作品**

在我认识的人里，老阳对人脑认知过程的理解数一数二。他读得多，写得多，脑子里有一套很强的索引，工作流和工具却极简。写匠很像他的思维方式做成了软件。

它默认你有大量可供检索的材料，把拆开再组合当作写作的常规动作，用随时可以回退给人试错的底气，也让 AI 待在不抢戏的位置。

这个念头，老阳 2013 年就有了。此后两次组队，两次都没做成。他说，那时以为写匠这个跟同学们吹过的牛，再也实现不了了。今年，他自己把它做完了。

我自己也在做类似的产品，一款是记录听与说上下文的通用 App Hemory，另一款是融入我个人工作流习惯的 AI Vault 笔记工具，主要面向产研场景。所以我懂这个过程。把想法做成作品，自己先得每天用着顺手、信得过，才谈得上交给别人。写书也是同样的道理。

如果你准备认真写一本书，正为论文发表头疼，或者想把多年的积累写成一部完整的作品，不妨试试写匠。它值得体验，也值得付费。

## 💡 07 写给会员的几个注意事项

2026-09-27 起陆续发布，覆盖 AI 搜索、问小文、AI 引擎、云备份、与 AI/Agents 协同、查看用量六个主题。

### 1 · AI 搜索

升级为会员（pro / pro+）后，第一时间请开启「AI 搜索」，可将你全库所有卡片自动转换为向量。

**向量模型**：谷歌今年新出的 `embeddinggemma:300m-q8_0`。支持 100 多种语言、3 亿参数、2k 上下文窗口，将卡片转换为 768 维度向量。做了精心的量化与评测，放弃谷歌官方 Q4 量化，改为 q8 量化，性能更卓越。

**如何下载**：在「设置」的「AI」的「AI 搜索」点击下载即可；之后全库卡片转向量是自动化过程。转换好后，在「对话」检索时能看到「意近」类结果，表示基于向量相似性的检索。

> **官方介绍**：EmbeddingGemma 是最先进的多语言嵌入模型，专为速度和效率设计，3.08 亿参数 + 2K 上下文窗口，为移动 RAG 管道、代理程序开启新可能；支持 100 多种语言，撰写时为 MTEB 上排名最高的 5 亿以下文本专用多语言嵌入模型。

### 2 · 问小文（对话界面）

写匠的「对话」界面设计精巧，包含很多功能，未来还会更多。毕竟推崇的是：**对话即生产**。

- **free 用户**：默认调用「关键词」检索，高性能算法、秒速索引秒速检索；但只关键词匹配，无法语义检索与 AI 问答。
- **pro / pro+**：点击「问小文 ai」开关（升级后默认开启），转为语义检索与 AI 问答模式。下载向量模型建好索引后，AI 先按向量相似性找到全库最相似卡片，综述成一段话启发灵感。

**卡片标记**：「含」＝关键词击中；「意近」＝语义击中。鼠标放卡片上有三种选项：**复制**（可在设置配置句子 / 段落 / 卡片范围，默认段落）、**参照**（右边打开）、**打开**（光标跳到关键词处）。还可查看所有卡片、换个关键词检索。

### 3 · AI 引擎

目前 pro / pro+ 支持两种引擎：

- **云端引擎**：最省时间、性能不错；风险是调用云端引擎校对时，稿件会发送到云端服务器。
- **本地引擎**：下载活水模型（42model）后下载模型到本地，完全离线，适合高机密单位或大规模作业。

| 用途 | 推荐模型 |
|---|---|
| 校对模型 | `aiwriter-check:v1-preview-q5_k_m`（中文校对大模型 V1 预览版） |
| 排版模型 | `aiwriter-typeset:v1-preview-q8_0`（Typst 排版大模型 V1 预览版） |
| 生成 · 配置好 | `glm-4.7-flash:30b-a3b-q4_k_m` |
| 生成 · 配置弱 | `minicpm5:2b-q4_k_m` |
| 生成 · 默认 | `qwen3.5:0.8b-q8_0` |

> **!** 本地引擎适配还不够，这段时间优先用「云端引擎」，十一假期之后再切「本地引擎」。若「AI 对话」性能下降，大概率是改成了本地引擎且用了小参数生成模型——切回云端即可。

### 4 · 云备份

云备份在「设置」的「存储」开启。pro 容量上限 10G；pro+ 42G，多数写作项目够用。采取一种较为特殊的备份协议：**restic 协议备份**。

**原理**：每 30 分钟（写匠自动备份，但需要没关掉），将全库项目打成压缩包、加密、拆成碎片后上传云端。云端无法读取内容，存的只是拆成碎片后的加密内容。换电脑会提示取回云备份。

借助 restic 协议，云备份速度极快，小项目几乎秒速级，大项目久一些；可在写匠云端查看备份进展与占用空间。可不开启，或开启后再关闭删除。

> **未来**：可能写一套私有 NAS / 服务器上的 restic 备份插件，把仓库备份到自己 NAS 而非云端，更安全：本地 NAS 备份 + 本地大模型，完全无需经过云端。

### 5 · 与 AI/Agents 协同

因为写匠自带 CLI，这类功能实现起来非常简单。直接告诉你的 Agents（如 Claude Code）：*请帮我实现写匠当前项目 / 当前卡片 / 某某项目 / 某某卡片，发布为微信公众号后台素材库。*
